# 统一推理资源与离线生命周期：验证记录

日期：2026-09-16。

## 实现

- CPU 离线片段与实时会话租借同一个固定实例池，默认容量为 4，移除 engine 内二次扩容；池完整初始化后才发布就绪状态。
- `long_audio.py` 管理离线分段、调度、汇总与收尾；Router 管理后端和租借，engine 公开 `transcribe_segments`。
- 音频准备在线程池执行；离线任务拥有文件生命周期。取消时停止排队工作，等待已开始的 native 调用结束，再释放实例和文件。
- 两个 HTTP 协议复用离线服务；响应断连与发送失败均回收任务。共享 VAD 推理使用已有互斥锁，避免模型共享状态竞争。

## 真实模型对照

环境：Apple M5 Pro、18 逻辑核、64 GiB 内存、macOS 27 arm64、Python 3.11.10、Torch 2.3.1。使用本地缓存 Qwen3-ASR-0.6B 和 ForcedAligner-0.6B；本机 SciPy 动态库问题通过隔离的 SciPy 1.16.3／NumPy 1.26.4 环境绕过，项目依赖未修改。

旧策略对照恢复基线 `82e0ac6` 的整请求租借和内部扩容，其余生命周期及 VAD 修复保持一致，因此不是两个完整历史提交的比较。耗时包含准备、VAD、ASR、对齐及清理；双请求列为整批耗时中位数。

| 输入与策略 | 实际实例数 | 单请求 | 双请求整体 |
| --- | ---: | ---: | ---: |
| 22 秒、4 片段，统一池 | 4 | 1.495 秒 | 2.923 秒 |
| 22 秒、4 片段，旧策略 | 4 | 2.616 秒 | 3.080 秒 |
| 22 秒、4 片段，统一池 | 2 | 2.428 秒 | 4.722 秒 |

| 30 秒、1 片段，旧策略 | 4 | 5.173 秒 | 6.589 秒 |

四片段生产 4 实例每种并发度有 6 次观测，对照与生产 2 实例各 3 次。自然单片段按新、旧、旧、新顺序复测，两组每种并发度各 6 次观测。

同预算下多片段单请求耗时降低 42.9%，双请求整体降低约 5.1%；后者不足以宣称显著吞吐提升。自然单片段首轮差异在交换顺序后反向，合并差异小于 0.2%，无稳定加速或退化证据。同预算下峰值 RSS 基本相同，约 8.2 GiB，没有内存优化证据。

四请求补测共 3 批，中位耗时 5.240 秒，实例始终为 4；此项没有同期旧版对照。最终 84 次计时转写按输入分组，全文、片段、字词与时间戳的完整结果哈希一致。仅覆盖两个中文输入，无人工参考文本，不能报告 CER/WER，也不代表 GPU 或长期生产容量。
