# R2T2 CPU 实验结论

R2T2 权重能够复用现有 Rust CPU 计算内核。服务已接入原生生成 FFI，使用 HF tokenizer 的精确 token IDs，共享一份 ASR 权重，分别保留实时与离线请求状态；离线继续独立重识别，对齐模型独立加载。官方 llama.cpp 也能纯 CPU 运行，当前保留为对照路径。

## 离线性能

RTF 为推理耗时 / 音频时长，越小越快。Rust 为跳过首次后的两次平均；llama 为同进程第二轮结果；CUDA 为后两次请求平均，含 HTTP 开销。它们不是相同硬件、语言条件或完整 API 链路的基准，不应用来推导精度优劣。

| 路径 | 中文 RTF | 英文 RTF | 拼接 RTF | 44.22s RTF | 进程峰值 RSS |
| --- | ---: | ---: | ---: | ---: | --- |
| Rust ARM64 INT8 decoder | 0.118 | 0.128 | 0.081 | 0.084 | 8.15–8.49 GiB |
| Rust BF16 权重路径 | 0.137 | 0.155 | 0.097 | 0.095 | 10.41–10.74 GiB |
| 官方 llama Q8 / F16 | 0.112 | 0.149 | 0.126 | 0.111 | 最高约 5.39 GiB |
| CUDA 共享引擎 | 0.011 | 0.013 | 0.007 | 0.006 | 未在此记录测量 |

Rust INT8 仅指 decoder 路径，不是整个模型全 INT8；BF16 权重路径转为 FP32 计算，不是原生 BF16 CPU 运算。llama 中文、英文分别指定 Chinese、English；Rust 旧离线与 CUDA 探针为自动语言，混合样本默认自动语言。RSS 包含各进程依赖与临时内存，不等同权重文件大小。

## 实时与接口

| 路径 | 观测 | 状态 |
| --- | --- | --- |
| 旧 Rust 流式 2s | 中文/英文计算 2.00s / 2.12s | 混合丢词，不能仅换权重上线 |
| 旧 Rust 流式 160ms | 中文/英文计算 14.79s / 16.64s | 慢于音频并出现重复 |
| 官方 llama 流式 | 160ms RTF 1.75–3.46；640ms 混合 RTF 1.71 | 累计重编码，未验证长会话窗口 |
| 新 CPU 服务修正前 2s / 640ms | 44s 拼接漏语言内容 | 失败记录保留，不作为验收通过 |
| 新 CPU 服务 640ms + 160ms 停顿检测 | 中英及拼接首字约 2.29–2.34s | 44.22s 回放保留三轮中英内容 |

新服务按真实录音速度发送 160ms 音频帧，停顿检测与解码步长独立；中英、混合、44s 的收尾延迟分别约 0.307 / 0.352 / 0.356 / 0.676s，44s 墙钟耗时 44.896s。这些是单轮样例，不能外推小时级会话或并发吞吐。旧内核和 llama 的无等待回放时间不等同真人首字延迟。

完整 CPU API 初轮中文、英文、混合、44s 均返回 HTTP 200、说话人和时间戳；这只验证链路完成。首个中文请求 10.67s 含首次加载，英文 1.36s、混合 1.70s、44s 17.20s，不与上表纯转写混算。

## 未通过与限制

- 自动语言整段识别在 14.24s 混合音频上丢失中文，Rust 两种精度、llama 与 CUDA 参考都存在该现象；CPU 完整 API 同样保留这一失败。llama 强制 Chinese 能恢复混合内容，但不能全局强制中文掩盖问题。
- 44s 样本由两份来源音频重复拼接，完整 API 分出六个标签；没有人工说话人标注，不能宣称说话人准确率通过。
- 初轮完整 API 静音请求出现 `Response ended prematurely`；对应代码已修正并有单元检查，真实静音接口复测尚未记录于此初轮文件，不声明全部通过。
- 原始 Rust 中文对齐曾将句号定位到 6.80s，超出 6.74s 音频；服务使用统一对齐单位与时长修正，不能直接透传 native 标点时间戳。字词仍可能零时长，时间边界正确不等于人工对齐准确。
- 没有人工逐字真值、真实会议评测、长时稳定性和并发内存结论。下一步验收应固定语言条件，补混合语言、说话人标注及静音复测，再评估部署范围。
